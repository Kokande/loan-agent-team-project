# Агент поддержки кредитования МСБ

Постановка и решения зафиксированы по [схеме проекта](Screenshot_20261029_232409.png). Они описывают целевое решение; в репозитории пока находится начальный каркас.

## Постановка задачи

Разработать агента, который обрабатывает обращения клиентов малого и микробизнеса по вопросам кредитования. Агент должен использовать промпты, искать информацию в нормативных документах через RAG, получать данные клиентов через инструменты доступа к БД и корректно передавать обращения оператору.

Результат — простой чат, сервис агента и векторная БД, запускаемые через Docker Compose. Тон ответов — формальный и профессиональный.

## Принятые решения

| Область | Решение со схемы |
| --- | --- |
| Архитектура | Отдельные frontend, сервис агента и БД; совместный запуск через `docker-compose.yaml`. |
| Backend | Python, FastAPI, LangChain/LangGraph. Конкретная связка библиотек требует уточнения. |
| Хранилище | PostgreSQL + pgvector для векторного поиска; работа с контекстом через PostgreSQL. |
| Frontend | Минимальный чат в рамках одной сессии; при обновлении страницы чат начинается заново. |
| API | Асинхронное взаимодействие через `/api/v1/invoke` и `/api/v1/get`; контракты пока не определены. |
| Обработка сообщений | Сообщения, поступившие во время работы агента, ставятся в очередь. |
| Возможности агента | Навыки, инструменты получения дополнительной информации и данных клиентов, контекст, RAG, формирование понятного пользователю ответа. |
| Контроль качества | Оценка RAG и агента (eval); агент-критик процесса связан с формированием ответа. |

## Первые задачи

1. Собрать каркас агента.
2. Настроить RAG: запрос на входе → релевантные чанки на выходе; провести оценку качества поиска.
3. Сделать минимальный frontend и собрать компоненты в `docker-compose.yaml`.

При дальнейшей разработке подключить данные клиентов, контекст, очередь сообщений, формирование ответа и оценку работы агента.

## Открытые вопросы

- Конкретные сценарии обращений клиентов.
- Условия и порядок передачи обращения оператору.
- Контракты API, формат контекста и правила обработки очереди.
- Набор нормативных документов, схема данных клиентов и критерии eval.

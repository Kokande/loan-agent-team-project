# RAG по нормативным документам

Модуль `backend/src/rag` реализует блок со схемы: запрос → релевантные чанки. Агент получает текст вместе с источником, редакцией, страницей PDF и score. Генерацию ответа выполняет основной агент.

## Запуск через Docker Compose

### Локальный режим (по умолчанию)

Из корня проекта, при `RAG_EMBEDDING_PROVIDER=ollama`:

```bash
cp .env.example .env
docker compose up -d db ollama
docker compose exec ollama ollama pull bge-m3
docker compose run --rm rag init-db
```

Первое скачивание модели требует интернета и места на диске. По умолчанию используются локальные эмбеддинги [bge-m3 через Ollama](https://ollama.com/library/bge-m3); платный API не нужен. БД и модель сохраняются в Docker volumes. Порты БД и Ollama доступны только на localhost. `rag` — CLI-контейнер, запускаемый по команде, а не постоянный HTTP-сервис.

Ollama включена в профиль `local`. Команда выше запускает её явно; альтернативный запуск — `docker compose --profile local up -d`. CLI зависит только от БД, поэтому для локального режима сначала запусти Ollama указанной командой.

### Облачный режим

Скопируй `.env.example` в `.env` и замени параметры эмбеддингов:

```dotenv
RAG_EMBEDDING_PROVIDER=api
RAG_EMBEDDING_API_BASE_URL=https://YOUR_WORKSPACE_ID.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1
RAG_EMBEDDING_API_KEY=YOUR_API_KEY
RAG_EMBEDDING_MODEL=text-embedding-v4
RAG_EMBEDDING_DIMENSIONS=1024
RAG_EMBEDDING_BATCH_SIZE=10
```

Это пример для Alibaba Cloud Model Studio в регионе Singapore: замени `YOUR_WORKSPACE_ID` и `YOUR_API_KEY` значениями из консоли. Для другого региона используй его URL и ключ. Адрес, модель, размерности и лимиты описаны в [официальной документации Alibaba](https://www.alibabacloud.com/help/en/model-studio/text-embedding-synchronous-api).

Запусти БД и создай индекс:

```bash
docker compose up -d db
docker compose run --rm rag init-db
```

Ollama не запускается, модель локально не скачивается. Ключ передаётся из `.env` в окружение контейнера; `.env` исключён из Git. Python вне Docker использует те же переменные, экспортированные в окружение. `init-db` не обращается к облаку и не проверяет работоспособность ключа — первый вызов API происходит при загрузке или поиске.

Можно подключить другой сервис с совместимым `POST /embeddings`: он должен принимать Bearer-ключ и поля `model`, `input`, `dimensions`, `encoding_format: float`, возвращать `data` с `index` и `embedding`. Указывай базовый URL без конечного `/embeddings`. Для облака требуется HTTPS; HTTP разрешён только для loopback при разработке. Перенаправления запросов с ключом не выполняются.

При загрузке фрагменты документов отправляются выбранному провайдеру, при поиске отправляется вопрос. Адаптер обрабатывает максимум 10 текстов на HTTP-запрос, даже если общий `RAG_EMBEDDING_BATCH_SIZE` больше; порядок восстанавливается по `data[].index`. HTTP 429 и временные 5xx повторяются максимум два раза. Если `Retry-After` больше 30 секунд или некорректен, вызов завершается ошибкой без раннего повтора. Ошибки ключа 401/403 не повторяются; сообщения ошибок не содержат ответ поставщика и API-ключ.

### Загрузка и поиск (оба режима)

Помести нормативный документ в `data/regulations/` (содержимое каталога не попадает в Git) и загрузи его:

```bash
docker compose run --rm rag ingest /documents/regulation.pdf \
  --source lending-policy \
  --title "Правила кредитования МСБ" \
  --revision "Редакция 1" \
  --effective-date 2026-10-01

docker compose run --rm rag query "Какие документы нужны для заявки?" --top-k 5
```

Название, редакция и дата в примере — образцы аргументов, их нужно заменить метаданными своего документа. Реальные нормативные документы в репозиторий не добавлены.

Поддерживаются UTF-8 `.txt`/`.md`, `.pdf` с текстовым слоем и `.docx`, включая текст таблиц. Сканы сначала нужно обработать OCR. Страницы PDF без извлекаемого текста пропускаются; PDF без текста целиком отклоняется. У TXT/MD/DOCX номер страницы равен `null`, поскольку достоверной пагинации у них нет.

`source` — стабильный уникальный идентификатор документа, а не его редакции. Для новой редакции повтори `ingest` с тем же `--source`: прежние чанки заменяются одной транзакцией. Повтор неизменённого документа возвращает `updated: false`. Изменение метаданных или настроек чанкинга вызывает повторную индексацию. Ошибка чтения, эмбеддингов или записи не удаляет прежнюю редакцию.

Отменённый документ можно убрать из поиска:

```bash
docker compose run --rm rag delete --source lending-policy
```

Корпус должен содержать применимые редакции. `effective_date` — метаданные для цитирования; модуль не определяет юридическую силу и не фильтрует документы по дате автоматически. История предыдущих редакций в этой версии не хранится.

## Подключение к агенту

Из `backend/`, после установки `pip install -e '.[dev]'`:

```python
from src.rag import create_rag

rag = create_rag()  # RAG_DATABASE_URL и остальные настройки из окружения
chunks = rag.retrieve("Какие документы нужны для заявки?", top_k=5)

for chunk in chunks:
    print(chunk.text, chunk.source, chunk.revision, chunk.page, chunk.score)
```

Для собственного векторизатора создай `RAGService(store, embedder)`, где `embedder` реализует `model: str`, `dimensions: int` и `embed(texts: list[str]) -> list[list[float]]`. Эмбеддинги документов и запросов должны принадлежать одной модели и векторному пространству. Готовые `OllamaEmbedder` и `APIEmbedder` доступны из `src.rag`; при ручной сборке передавай в `PgVectorStore` идентификатор `model=embedder.model`.

`retrieve` возвращает `list[SearchResult]` с полями `source`, `title`, `revision`, `effective_date`, `chunk_index`, `text`, `page`, `score`. Пустой корпус возвращает `[]`. По умолчанию возвращаются ближайшие чанки без порога. Можно передать `min_score`, но его нужно подобрать на размеченных вопросах: косинусная близость не является вероятностью корректного ответа. Пустой результат или отсутствие подтверждающей нормы должен обрабатываться основным агентом.

Методы синхронные. Из асинхронного FastAPI/LangGraph вызывай их через `await asyncio.to_thread(rag.retrieve, query, top_k=5)`, чтобы не блокировать цикл событий. Модуль не занимает маршруты `/api/v1/invoke` и `/api/v1/get`.

Текст документов передаётся в контекст агента как данные источника. Инструкции внутри найденного текста не должны менять системный промпт и правила работы инструментов.

## Настройки

| Переменная | Значение по умолчанию / назначение |
| --- | --- |
| `RAG_DATABASE_URL` | Обязательная строка подключения Psycopg: URL или libpq conninfo. |
| `RAG_EMBEDDING_PROVIDER` | `ollama` по умолчанию; `api` — облачный совместимый API. |
| `RAG_OLLAMA_URL` | `http://localhost:11434`; внутри Compose — `http://ollama:11434`. |
| `RAG_EMBEDDING_API_BASE_URL` | Обязателен для `api`, без суффикса `/embeddings`. |
| `RAG_EMBEDDING_API_KEY` | Обязателен для `api`; не используется для Ollama. |
| `RAG_EMBEDDING_MODEL` | `bge-m3` для Ollama; для `api` модель нужно указать явно. |
| `RAG_EMBEDDING_DIMENSIONS` | `1024`. В облачном режиме также передаётся в запросе как `dimensions`. |
| `RAG_EMBEDDING_TIMEOUT` | `120` секунд на запрос, включая загрузку модели. |
| `RAG_EMBEDDING_BATCH_SIZE` | `16` чанков на вызов векторизатора. API дополнительно разбивает пакет на группы до 10 текстов. |
| `RAG_CHUNK_SIZE` | `1600` символов на чанк. |
| `RAG_CHUNK_OVERLAP` | `200` символов перекрытия в пределах страницы. |

Python сам не читает `.env`: экспортируй нужные переменные в окружение. Compose читает `.env` автоматически. Внешний Python использует адреса localhost из `.env.example`; CLI-контейнер использует внутренние адреса и реквизиты `POSTGRES_*`. При изменении пароля в URL внешнего подключения требуется URL-encoding.

`init-db` требует прав на `CREATE EXTENSION vector` и создание схемы. Все таблицы находятся в схеме `rag`, данные клиентов не затрагиваются. Используется точный косинусный поиск pgvector без приблизительного индекса. Модель и размерность записываются в `rag.settings`; несовместимая настройка отклоняется даже при совпадающем числе измерений. Для смены модели используй отдельную БД и загрузи весь корпус заново. Если обновляешь веса под тем же тегом Ollama, также потребуется полная переиндексация; для воспроизводимости фиксируй версию модели.

В облачном режиме `embedder.model` — идентификатор, составленный из модели и SHA-256 базового URL, а `embedder.model_name` — имя модели для API. Ключ не включается в идентификатор. Смена провайдера или базового URL требует отдельной БД и повторной индексации; ротация ключа при прежнем endpoint этого не требует. Прежние индексы Ollama совместимы без миграции.

Адаптер Ollama использует [`POST /api/embed`](https://docs.ollama.com/api/embed) с `truncate: false`: слишком длинный текст вызывает ошибку вместо потери конца документа.

## Оценка поиска

Подготовь JSONL с реальными вопросами и ожидаемыми `source`, затем помести файл в `data/regulations/`, например `eval.jsonl`:

```json
{"query":"Какие документы нужны для заявки?","expected_sources":["lending-policy"]}
{"query":"Какие требования предъявляются к обеспечению?","expected_sources":["collateral-policy","lending-policy"]}
```

Это пример формата, а не готовый размеченный датасет.

```bash
docker compose run --rm rag eval /documents/eval.jsonl --top-k 5
```

Вывод: средний Recall@k по уникальным ожидаемым источникам и MRR первого релевантного чанка, а также результаты каждого вопроса. Повторные чанки одного источника не увеличивают Recall. Порог качества команда выбирает после разметки корпуса; синтетические тесты не доказывают качество поиска по реальным нормативным документам.

## Проверки

```bash
cd backend
python -m pip install -e '.[dev]'
python -m pytest
python -m ruff check .
```

Юнит-тесты не требуют Ollama, интернета и PostgreSQL. Интеграционные тесты включаются через `RAG_TEST_DATABASE_URL`, указывающий на отдельную тестовую БД с pgvector: тесты создают и удаляют в ней схему `rag`. Без этой переменной они явно пропускаются. Полный путь CLI проверяется для обоих провайдеров; HTTP-сервис модели в тестах локальный, реальный платный API не вызывается.

```bash
RAG_TEST_DATABASE_URL='postgresql://USER:PASSWORD@localhost:5432/loan_agent_test' \
  python -m pytest tests/test_postgres.py -v
```

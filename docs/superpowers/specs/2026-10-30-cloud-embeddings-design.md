# Облачные эмбеддинги RAG

Пользователь подтвердил добавление облачного адаптера к существующему RAG. Сохраняем локальную Ollama по умолчанию; pgvector, загрузка документов и интерфейс агента остаются прежними.

## Решения реализации

- Выбор `RAG_EMBEDDING_PROVIDER=ollama|api`. Облачный адаптер вызывает совместимый `POST /embeddings` с Bearer-ключом, `model`, `input`, `dimensions`, `encoding_format=float`.
- Общий HTTP-адаптер выбран вместо SDK одного поставщика: достаточно стандартной библиотеки, базового URL и ключа. Пример подключения — Alibaba Model Studio `text-embedding-v4`.
- В облачном режиме URL, ключ и модель обязательны; запросы не выполняются при создании объекта или `init-db`.
- Результаты восстанавливаются по `data[].index`, проходят прежнюю проверку количества, размерности и значений float32. Запросы разбиваются на пакеты не более 10 текстов для совместимости с Alibaba.
- HTTP 429 и временные 5xx повторяются не более двух раз с задержкой; ошибки авторизации не повторяются. Ответы поставщика, тексты документов и ключи не включаются в сообщения ошибок.
- API требует HTTPS; HTTP разрешён для loopback-сервера разработки. Перенаправления запрещены, чтобы не пересылать заголовок авторизации другому endpoint.
- Идентификатор облачного векторного пространства включает модель и хеш базового URL; ключ в него не входит. Переключение провайдера/endpoint требует отдельной БД и переиндексации; ротация ключа не меняет индекс. Старые идентификаторы Ollama сохраняются.
- Compose запускает Ollama только по явному запросу/профилю `local`; CLI зависит только от БД. Облачный режим не требует скачивания модели.

## Проверка

Тесты контракта API, порядка векторов, пакетирования, ошибок, конфигурации и изоляции индекса. Полный путь CLI проверяется для обоих провайдеров на временном HTTP-сервере и настоящем PostgreSQL + pgvector. Живой платный API без ключа не вызываем.

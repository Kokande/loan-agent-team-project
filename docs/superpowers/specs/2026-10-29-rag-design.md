# RAG по нормативным документам

## Назначение и границы

Реализовать блок со схемы: запрос → релевантные чанки нормативных документов. Генерация ответа, клиентские данные, frontend и API агента остаются задачами других участников.

В репозитории нет нормативных документов и выбранной модели эмбеддингов. Решения ниже — технические допущения реализации, которые можно изменить настройками.

## Подход

Выбран самостоятельный Python-модуль с Psycopg и pgvector: его можно вызвать из любого агента, включая LangChain/LangGraph. Обёртка LangChain сейчас добавила бы зависимость без необходимости; отдельный HTTP-сервис дублировал бы будущий backend.

- Загрузка UTF-8 TXT/Markdown, PDF с текстовым слоем и DOCX с таблицами.
- Разбиение на чанки с перекрытием, предпочтительно по абзацам и предложениям. Сохраняются источник, заголовок, редакция, дата вступления в силу и страница PDF.
- Локальные эмбеддинги через Ollama, по умолчанию `bge-m3`, 1024 измерения. Текст не обрезается молча: превышение контекста — ошибка. Векторизатор подменяется через Python-протокол.
- PostgreSQL хранит документы и чанки в схеме `rag`. Точный поиск по косинусному расстоянию через pgvector; приблизительный индекс пока не нужен для небольшого корпуса.
- Стабильный `source` обозначает документ. Повтор той же загрузки не создаёт дубликатов. Новая редакция атомарно заменяет чанки; ошибка эмбеддингов или записи сохраняет прежнюю редакцию.
- В одной схеме нельзя смешивать модели или размерности. При смене модели нужен отдельный индекс/БД и повторная загрузка.
- Возвращаются текст, score и сведения для цитирования. Порог score задаётся вызывающим кодом и требует калибровки; score не является вероятностью правильного ответа.
- CLI: инициализация БД, загрузка, поиск, удаление документа, eval. Eval считает source-level Recall@k и MRR по размеченным вопросам.

## Проверки и ограничения

Юнит-тесты проверяют загрузку, чанкинг, ошибки эмбеддингов, повторную загрузку и метрики. Интеграционные тесты с отдельной тестовой БД проверяют реальный pgvector, замену редакции, откат транзакции и защиту от смешивания моделей.

Сканы требуют внешнего OCR. Актуальность нормативных документов контролирует владелец корпуса: дата сохраняется как метаданные, юридическая применимость автоматически не определяется. Качество поиска оценивается на реальных документах и размеченных вопросах после их предоставления.

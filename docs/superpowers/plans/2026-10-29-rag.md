# RAG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Загрузка нормативных документов и retrieval через PostgreSQL + pgvector.

**Architecture:** Независимый Python-модуль в `backend/src/rag`, адаптер эмбеддингов Ollama, транзакционное хранилище pgvector и CLI. Генерация ответа находится за границами модуля.

**Tech Stack:** Python >=3.11, Psycopg 3, pgvector, pypdf, python-docx, Ollama.

**Spec:** `docs/superpowers/specs/2026-10-29-rag-design.md`.

## Global Constraints

- Не менять код агента и frontend; не добавлять платные API и реальные клиентские данные.
- По умолчанию `bge-m3`, 1024 измерения; одна модель на схему `rag`.
- Метаданные источника и страницы должны доходить до результата поиска.

## Review Focus

- Пустые документы и сканы: понятная ошибка без удаления прежних чанков.
- Повторная загрузка и новая редакция: отсутствие дубликатов, атомарная замена.
- Ошибочные/нулевые/нечисловые векторы: отказ до записи.
- Смена модели с той же размерностью: отказ, а не смешивание векторов.
- Пустой корпус, порог score и кавычки в source: корректный поиск и параметризованный SQL.

## Проверка реализации

- Все 45 тестов прошли, включая 6 интеграционных на временном PostgreSQL 16.2 + pgvector 0.6.2.
- Проверен путь CLI: загрузка → повторная загрузка → поиск → eval → удаление. В этом тесте только модель заменена тестовым HTTP-сервисом.
- Пакет установлен через `pip install -e './backend[dev]'`; CLI доступен вне каталога проекта.
- `ruff check backend`, `git diff --check` и `docker compose config --quiet` прошли.
- Независимая проверка кода: исправлена потеря точности float64 → float32, добавлены проверки переполнения и превращения в нулевой вектор (RED → GREEN).
- Сборка Docker и запуск настоящей модели Ollama не проверены: Docker daemon недоступен. Нормативный корпус и разметка не предоставлены, качество реального поиска пока не измерено.
